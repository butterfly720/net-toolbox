# NetToolbox · 网络工具站

一个**纯前端**的网络计算与查询工具集。零框架、零构建、零依赖、**零后端**。

> **技术要点**：所有功能要么在浏览器本地用算法算出来，要么通过公共 DoH（DNS over HTTPS）接口完成 —— 没有任何自己的服务端。

## 功能一览

| 工具 | 说明 |
|---|---|
| **IPv4 子网计算器** | 输入任意 IP 与掩码，得到网络地址、广播地址、可用主机范围、反掩码，并可视化 32 位二进制结构 |
| **子网划分** | ① 按数量等分；② VLSM 变长划分（按各部门实际主机数分配，减少地址浪费） |
| **VLAN 规划器** | 自动生成整套校园网 VLAN 方案：VLAN ID、网段、网关、DHCP 池；可导出 Markdown 表格与 Cisco 配置片段 |
| **DNS 在线查询** | 支持 A / AAAA / CNAME / MX / TXT / NS / SOA / SRV / CAA / PTR 记录，自动切换多个 DoH 提供方 |
| **IP 进制换算** | 点分十进制 ↔ 32 位整数 ↔ 二进制 ↔ 十六进制 |

## 技术难点记录

这一节是给面试准备的：讲清楚「难在哪、怎么解决的」。

### 1. 用 DoH 绕过浏览器沙箱

**问题**：静态站点没有后端，而浏览器不允许 JavaScript 直接发送 DNS 查询（UDP 53 端口不可用）。
用 `fetch` 请求 DNS 服务器也不行 —— DNS 是二进制协议，且浏览器只允许 HTTP(S)。

**解法**：使用 **DNS over HTTPS（DoH）** 接口。公共 DNS 服务商把 DNS 查询封装成普通 HTTPS
请求，返回 JSON 格式结果，且响应头带有 `Access-Control-Allow-Origin`，因此前端可以直接调用。

```
GET https://cloudflare-dns.com/dns-query?name=example.com&type=A
Accept: application/dns-json
```

**进一步处理**：
- 不同提供方的返回字段不完全一致，写了一个 `normalize()` 做统一归一化
- 按顺序尝试多个提供方（Cloudflare → 阿里公共 DNS → Google），前一个失败自动降级
- 用 `AbortController` 加 12 秒超时，避免网络不通时请求一直挂起
- `dns.google` 在中国大陆不可访问，因此放在列表最后；阿里公共 DNS 作为国内主力

### 2. JavaScript 位运算的 32 位陷阱

**问题**：JS 的位运算符（`<<`、`>>`、`&`、`|`）会把操作数当作**有符号 32 位整数**处理。
计算 `255.255.255.255` 对应的整数时，结果会变成负数 `-1` 而不是 `4294967295`。

**解法**：
- 所有位运算结果一律用 `>>> 0` 转成无符号数
- IP 转整数时用**乘法累加**（`n = n * 256 + seg`）而不是左移，从根源避开符号问题
- 掩码全 1（`/32`）单独处理，因为 `0xFFFFFFFF << 0` 在 JS 里是有符号的

### 3. 前缀位数的反推

**问题**：用户输入的是「需要 100 台主机」，要反推出该用 `/25`。

**解法**：可用主机数 = 2^主机位数 − 2（扣掉网络地址与广播地址），
所以要找最小的 `bits` 使得 `2^bits − 2 ≥ 需求`，前缀 = `32 − bits`。

```
需求 100 台 → 2^7 − 2 = 126 ≥ 100 → 主机位 7 位 → /25
```

### 4. 边界前缀的处理

`/31` 与 `/32` 不符合「减 2」的常规公式：

| 前缀 | 常规公式结果 | 实际情况 |
|---|---|---|
| /32 | 0（错） | 单主机，可用 1 个地址 |
| /31 | 0（错） | RFC 3021 点对点链路，两端都可用，共 2 个 |

代码里对这两种情况单独分支处理。

### 5. VLSM 的贪心分配

**问题**：多个部门需求不同（100 / 50 / 20 / 6 台），如何划分子网最省地址？

**解法**：**按需求从大到小排序后再分配**。这样大块排在前面、小块补后面的空隙，
能最大限度减少碎片。分配时维护一个游标 `cursor`，每次分配后前移该网段大小。

反例：如果从小到大分配，100 台的需求最后可能找不到连续空间。

### 6. CSS 变量做主题

全站配色集中在 `:root` 的 CSS 自定义属性里，改一处全站生效。
深浅色适配只需替换变量组，不用改任何组件样式。

## 设计取舍

| 决策 | 理由 |
|---|---|
| **不用框架** | 这个站点的核心价值在算法，不在 UI。引入 React 只会掩盖逻辑，也增加部署复杂度 |
| **算法与 DOM 分离** | 核心模块不依赖浏览器环境，才能用 Node 跑单元测试 |
| **先写测试再搭界面** | 子网计算容错为零（算错掩码会导致真实网络配错），必须先用测试锁住行为 |
| **DoH 而不是自建后端** | 免服务器、免备案、免运维。代价是依赖第三方服务可用性，用多提供方降级缓解 |
